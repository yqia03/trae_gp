## 二、作品信息

| 项目 | 内容 |
| --- | --- |
| 作品名称 | 就地取材 |
| 作品简介 | 「就地取材」把家里已有的食材和闲置物品转成可执行的晚餐菜单与旧物改造方案。用户拍照或录入清单，确认大致用量和限制，就能获得材料分配、步骤与缺料替代；常备食材仓库让油盐等用品不用每次重复添加。 |
| 目标人群 | 独居、合租的年轻人，以及希望减少食材浪费、重复采购和闲置物品堆积的家庭用户。 |
| 解决什么问题 | 面对现有食材不知道怎么组合成一餐；菜谱需要的材料与实际库存不匹配；油盐等常备品重复录入；闲置物品缺少简单可做的再利用方法。 |
| 核心主张 | 把家里已有的，变成今天用得上的。 |
| 参赛方向 | 生活创意：日常资源再利用。 |

## 三、核心功能与亮点

### 从「有什么」到「怎么做」

上传图片或手动录入后，用户可以编辑名称、数量和单位，并设置人数、目标时间、忌口等限制。「今晚吃什么」给出一餐菜单、各道菜的用量和步骤，以及整餐制作顺序。「物品第二人生」提供可选择的旧物改造用途、所需工具与成品检查，一次采用一种方案。

### 自动估量，降低输入负担

食材图片识别后自动填入大致克重、体积或个数。模型没有给出估量时，应用补入常见参考份量，并区分「图片估算」与「参考估算」。用户可以直接一次确认，也能自行修改，无需逐项称重；估量和计算出的余量均不代表精确测量。

### 常备食材仓库

用户可自行增删油、盐、酱油等常备品，调整数量、单位与是否使用。设置保存到当前浏览器，选中的用品在后续生成时自动带入；仓库和本次识别清单会合并，减少重复填写。

### 方案必须用得上

生成结果不仅是一段建议文字，还包含资源引用、具体用量、步骤和限制条件。默认服务端和自定义接口共享结构与资源校验规则，避免多道菜重复占用同一批食材。缺少材料时可尝试「这项没有，换个办法」，重新规划并说明差异；用户也能开启「只用已有资源」。

### 在线配置自己的 AI

GitHub Pages 在线版提供「AI 接口设置」：选择 Gemini 原生或 OpenAI 兼容类型，填写 HTTPS 接口地址、模型名称和自己的 API Key，即可启用或测试连接。自定义调用由浏览器直接发送到用户指定的服务，不依赖本站托管的 AI 后端；本地版本仍默认使用 Gemini 服务端。

配置与密钥只保存在当前页面内存中，刷新即清除，修改接口地址或切换接口类型会清空密钥，不写入浏览器持久存储或 Git。接口须允许浏览器跨域访问（CORS），图片识别需支持图片输入的模型，OpenAI 兼容接口还需支持 JSON 输出。

### 来源清楚，失败可恢复

页面区分「固定演示样例」、「Gemini 实时生成」和「自定义 AI 实时生成」（`source: custom`）。真实请求失败时保留输入、显示错误并允许重试，不自动回退样例；固定样例由用户主动加载。样例图片为 AI 生成的展示素材，不代表真实拍摄或实际改造后的成品。

## 四、技术实现

| 层次 | 实现 |
| --- | --- |
| 界面 | Next.js 16、React 19、TypeScript、Tailwind CSS 4、lucide-react；单页切换两种生活场景。 |
| 图片与生成 | 默认通过官方 `@google/genai` SDK 在服务端调用 Gemini；自定义模式由浏览器直连 Gemini 原生或 OpenAI 兼容接口。 |
| API | `/api/recognize` 识别资源；`/api/plan` 生成、替代与校验方案。 |
| 约束校验 | 默认服务端与自定义模式共享 Zod 结构及资源校验规则；应用汇总用量并计算余量。 |
| 本地保存 | `localStorage` 保存常备仓库，不提供跨设备同步；自定义接口及密钥仅在页面内存，不持久保存图片或密钥。 |
| 部署 | GitHub 保存源码并提供 Pages 静态托管，用户可自带接口直接调用 AI；默认 Gemini 服务端在本地或支持 Next.js 的平台运行。 |

默认服务端使用环境变量 `GEMINI_API_KEY` 和 `GEMINI_MODEL`。自定义模式在页面填写模型与密钥，由浏览器直接把密钥、图片和输入发送到用户指定的 HTTPS 接口。图片识别不会确认食品安全；对名称或用量不确定的内容，用户可在生成前调整。

## 五、作品展示

- 源码：[GitHub · yqia03/trae_gp](https://github.com/yqia03/trae_gp)
- 在线演示：[GitHub Pages 入口](https://yqia03.github.io/trae_gp/)（静态托管，可配置自己的 AI 接口）
- 完整 AI 版：[本地运行说明](../README.md#立即运行完整-ai-版本)

GitHub Pages 不能运行 Next.js 服务端 API。在线版既可展示固定案例、界面交互和常备仓库，也可通过用户自己配置的接口进行真实识别与生成；此时调用从浏览器直接发出，本站没有托管 AI 后端或公共密钥。

填写示例：Gemini 原生地址为 `https://generativelanguage.googleapis.com/v1beta`；OpenAI 兼容地址可填 `https://api.openai.com/v1` 或完整的 `https://api.openai.com/v1/chat/completions`。模型须为所填服务支持的型号，接口须开放 CORS；图片识别还需要视觉模型，OpenAI 兼容模式需要 JSON 输出支持。

### 推荐演示顺序（约两分钟）

1. **说明场景**：家里有食材和闲置物品，希望直接知道今天能怎么用。
2. **晚餐闭环**：加载「晚餐」演示样例，展示食材清单、菜单、具体用量、制作顺序和资源余量，展开并勾选做菜步骤。
3. **减少重复输入**：展开常备仓库，添加一种调味品，修改用量或勾选状态，刷新说明保存效果。
4. **资源再利用**：加载「旧物」演示样例，切换方案，展示材料占用与改造步骤。
5. **真实 AI**：在线版展开「AI 接口设置」，填写并启用自己的接口或测试连接；上传食材图片，展示自动估量，确认后生成菜单，并指出「自定义 AI 实时生成」来源标记。本地也可用默认 Gemini 服务端演示。
