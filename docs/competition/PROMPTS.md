# 复制给 TRAE 的提示词

本文件是用户在 TRAE 发出的执行指令素材。Codex 只准备；开发按比赛允许的时间开始。下面“正式开工”是完整入口，后面的短指令仅在对应阶段需要时使用，不必每轮重复全部规格。

## 赛前读取与环境确认（不写业务代码）

```text
这是「就地取材」TRAE 比赛项目，当前仍是赛前准备。先阅读 AGENTS.md 和 docs/competition/START_HERE.md；按需阅读 docs/competition/BRIEF.md、docs/competition/MODEL_CONTRACT.md。
只验证你能读取这套资料和 demo-ui、demo-check 两个项目 Skill，在终端确认 Node/npm/Git，并用内置浏览器打开一个普通网页读取标题。不创建应用、不安装业务依赖、不提交或推送。
告诉我：项目路径、资料是否可读、两个 Skill 是否可用、浏览器实际调用结果、Gemini 服务端需要配置的变量名。不要显示或读取密钥内容。
```

## 正式开工：一次复制这一段

```text
现在开始实现「就地取材」，业务代码全部由你 TRAE 在本机完成。编程窗口 15:40–17:20，香港时间，共100分钟；如果现在已晚于15:40，按实际剩余时间压缩计划，最后15分钟留给验收和交付。

先读取 AGENTS.md、docs/competition/BRIEF.md、docs/competition/DESIGN.md、docs/competition/MODEL_CONTRACT.md，以及 assets/manifest.json。模型提示词使用 docs/competition/LLM_PROMPTS.md；做到样例与验收时读取 assets/demo/scenarios.json 和 docs/competition/DEMO.md。按需读取，完成后不要每轮重新加载全包。

产品：把家里已有的变成今天用得上的。以「今晚吃什么」为主线：图片/手动输入 → 用户确认名称、数量、基础用品与限制 → 一餐菜单、材料用量、步骤与顺序。其次做「物品第二人生」的互斥改造方案。两者共享「巧用替代」：缺料后沿用已确认资源重新规划，说明结果差异并重新核算用量。

采用本包默认栈：Next.js 16 App Router + TypeScript + Tailwind 4 + npm + Zod + lucide-react + @google/genai。一个应用，两个服务端路由 /api/recognize 与 /api/plan；按 MODEL_CONTRACT 使用 Gemini Interactions API，默认模型 gemini-3.8-flash。不要把 generateContent 参数混进 Interactions。依赖以实际安装版本与锁文件为准，先核对 SDK 类型。

先检查现有目录与暂存修改。仓库非空，保留 AGENTS、docs、assets、.trae、.gitignore 和 Git 历史；脚手架若拒绝非空目录，在临时目录生成后有选择地迁入业务文件，不能清空项目或覆盖现有资料。保留 .env 忽略规则，补全应用依赖/构建产物忽略。不创建成员分支、不做多人协调、不强推，提交/推送遵循我的授权。

开始后前10分钟完成可启动骨架，并尽早用小图核验 Gemini 结构化请求。服务端读取 GEMINI_API_KEY 和 GEMINI_MODEL，密钥由我私下填入 .env.local；缺 key 就给出精确的本地配置指引并继续不依赖 key 的工作，不能假称真实调用通过，不要求我把密钥贴在聊天。失败先区分配置、网络、额度与模型可用性，避免盲目换框架。

先跑通食材闭环，再加旧物和替代。识别结果只是候选，重量、状态、材质不能从照片当作事实；用户确认后才规划。服务端按全餐汇总材料用量，工具不当耗材扣除。旧物按每个互斥方案单独核算。缺工具、份量或约束无法满足时说明缺什么，不偷偷添加材料或扩大时间。

视觉使用 docs/competition/DESIGN.md 和 assets/reference/ui-desktop-concept.png：暖深棕、奶油文字、紧凑主视觉、左输入右结果。用真正可交互组件实现，不把概念图直接贴成页面。复制品牌与演示图到 public/assets，展示明确的 AI 生成示例标记。概念图里的营养文案、收藏入口、时间数字不覆盖产品规格。

固定样例使用 assets/demo/scenarios.json 的预置内容，并适配统一契约；不把该文件当作现成接口响应。点击加载时同步切换图片、清单与结果，明显显示「固定演示样例」。任意自定义照片不可套固定识别结果；真实失败先报错，不自动伪装成功。更换输入使旧结果失效，慢请求不得覆盖新输入。

遵循 docs/competition/TEAM.md 时间表。到最后15分钟停止增加功能；可先删收藏与装饰，保住核心操作、错误恢复、来源和数量一致。每阶段短报完成项、验证证据与剩余风险，普通实现选择自行解决，只有影响P0或缺少必要凭据才指出具体缺口。

最后使用 demo-check Skill，实际在浏览器验证两场景、纠错、超量、替代、请求失败与样例恢复，检查桌面和窄屏。执行已建立的构建与类型/静态检查；无现成测试框架则只为资源守恒、输入失效等关键逻辑写必要测试，不搭大型测试工程。
交付实际启动命令、页面地址、文件变化、真实 API 状态、已通过/未验证项、剩余限制与90秒演示路径。若现场要求公网，再在已可用的部署平台发布并验证目标链接；未提供账号时先保住本地演示并明确该项待办。
现在直接按以上范围推进，不重新做选题，也不只返回计划。
```

## 主流程完成后：视觉收尾

```text
保持已验证功能，使用 demo-ui Skill，按 docs/competition/DESIGN.md 调整当前页面。重点检查：暖棕与奶油色、中文可读性、紧凑首屏、真正可用的输入和主按钮、明确结果来源、用量与步骤的阅读顺序。参考 assets/reference/ui-desktop-concept.png 的氛围，不复制其中业务承诺。
实际打开桌面与390px宽度页面，修复遮挡、无效入口和状态不清。不要新增收藏、后台或第三场景，完成后报告实际浏览器检查结果。
```

## 实现卡住：收缩与继续

```text
按当前实际剩余时间收缩范围，保留食材主闭环、用户确认、结构与用量验证、错误恢复和明确来源。优先删除P1和装饰，旧物如不能完成真实生成可保留明确标记的固定样例并记录限制。真实请求失败不得伪装成成功。
先定位阻塞的最小原因，给出脱敏错误、影响范围与一个修复动作，继续能独立推进的部分。不要换技术栈，不扩大范围，不重写已能运行的主线。
```

## 最后15分钟：冻结、验收与交付

```text
停止新增功能，使用 demo-check Skill 和 docs/competition/DEMO.md。实际跑通主要演示，再验证改数量、超量拒绝、旧物二选一、真实请求失败恢复、加载固定样例、输入改变使旧结果失效。执行当前有效的构建/类型检查。
只修阻断演示的问题。记录真实API、浏览器交互、部署各自是否通过，不把样例通过当真实通过。给出启动地址、90秒操作顺序、恢复初始状态方式、未验证项。按已授权范围保存版本，提交前重新检查暂存区是否包含最新文件，不能只提交赛前旧资料。
```
