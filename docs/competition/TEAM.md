# 100 分钟单机执行安排

用户已确定在一台电脑完成，沿用此文件路径；不再做队员分支与模块交接。Codex 准备资料，TRAE 在本机负责实现、运行和修复。以下是执行建议，不是官方赛规。

## 时间表

| 时间 / 分钟 | 优先工作 | 阶段出口 |
|---|---|---|
| 15:30–15:40 / 赛制说明 | 记录提交形式与路演时长等补充要求 | 更新必要约束，准备正式开工提示词 |
| 15:40–15:50 / 0–10 | 安全初始化非空仓库，启动 Next.js；尽早检查 Gemini key 与小图结构化请求 | 浏览器可打开；真实 API 成功或已有具体失败原因 |
| 15:50–16:10 / 10–30 | 双场景骨架、上传/手动输入、候选纠错、基础用品与约束确认 | 食材可以得到用户确认清单；错误输入可改正 |

| 16:50–17:05 / 70–85 | 浏览器验收、必要构建/类型检查；若必须公网则验证部署 | 核心验收有证据；提交入口确定 |
| 17:05–17:20 / 85–100 | 冻结、彩排、提交，仅修阻断问题 | 演示起始状态、最终版本、运行地址与限制清楚 |

若实际开始更晚，按剩余时间压缩功能；最后15分钟仍保留收尾。17:20之后茶歇不自动视为开发时间。

## 卡点处理

- 10分钟 API 未通：明确配置/网络/额度/模型权限原因，继续样例与界面，真实调用状态单独记录。
- 30分钟确认清单未通：停止装饰，先修输入与确认；不要跳过确认直接将照片当成可用库存。
- 55分钟晚餐未通：优先主闭环，旧物缩为明确标记的固定样例，记录实际覆盖；不把降级说成完整真实功能。
- 70分钟以后：不加收藏等P1，不换框架、不新增服务。按 DEMO 的故障清单修最影响演示的项。
- 真实失败不可自动切换为假成功，任何缩减都保留来源与资源用量一致。

## Git 与交付

Git 用于本机版本记录和交付，不创建成员分支或安排合并，也不删除既有权限。保存提交/推送遵循用户授权；不强推、不改写历史、不清空未提交内容。

当前有早先暂存的准备资料，最新修改仍需在提交前按 diff 重新暂存，避免只交旧版。初始化应用须合并保留 .gitignore 的密钥忽略规则，并加入 node_modules 与构建输出；禁止提交 .env.local。
