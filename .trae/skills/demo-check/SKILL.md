# 就地取材验收

读取 docs/competition/DEMO.md 与 BRIEF.md 的P0，资源规则按 MODEL_CONTRACT.md。以实际时钟或用户告知的剩余时间控制范围。

1. 明确验证对象：URL、版本、真实 Gemini 或固定样例。先找实际启动/构建/类型检查命令，不凭空声称存在测试脚本。
2. 从初始页走完整食材路径与旧物路径。确认识别只是候选，克数/基础用品由用户确认；真实与固定来源正确。
3. 核对全餐资源分配不超量，旧物按每个互斥方案单独计算。修改库存使旧结果失效；重新规划必须更新步骤、用量与缺项。
4. 验证一项资源不足、一项真实请求失败与恢复、输入变化时迟到响应处理。不能自动把真实失败伪装成固定样例成功。
5. 执行已有且必要的构建、类型检查和关键逻辑测试；没有框架时不为最后收尾搭建大型工程。修复后复测受影响项。
6. 实际检查桌面与窄屏；若要求公网，访问真实部署URL再记录通过。录屏、截图与样例不得说成实时模型结果。

输出每个P0的通过/失败/未验证及实际证据、真实API状态、启动方式、未完成限制与恢复演示起始状态。终端启动或JSON可解析不代表应用流程通过。
